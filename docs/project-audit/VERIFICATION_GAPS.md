# Verification Gaps & Unverified Operational Boundaries

**Project:** AstroLogic AI  
**Scope:** Transparent register of system behaviors, external integrations, production environments, and edge cases that could not be verified during the read-only discovery exercise.

---

## 1. Summary of Verification Constraints

During this audit, code inspection was performed on all active files, and safe, non-destructive automated test suites were executed (`174 passed, 1 skipped`). However, certain external dependencies, production infrastructure, and real-world runtime conditions could not be verified directly.

---

## 2. Detailed Verification Gaps

### 1. Live LLM API Generation & Token Costs
- **Unverified Aspect:** Live communication with OpenAI (`gpt-4o`) or Anthropic (`claude-3-5-sonnet`) models.
- **Reason:** No live third-party API keys (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`) were configured in local test environment; tests execute with mock LLM fallbacks ([`backend/modules/narrative/llm_client.py:44`](file:///c:/Desktop/astro_may_res%20(2)/astro-platform/backend/modules/narrative/llm_client.py#L44)).
- **Risk:**
  1. Real-world LLM latency (2–8 seconds) may cause timeouts in worker processes if Redis socket timeouts are too short.
  2. Hallucinations or astrological inaccuracies generated by LLMs are not currently bounded by a structured JSON schema parser.
  3. Cost per narrative prediction request under production user volume remains unmeasured.

---

### 2. High-Precision Ephemeris Numerical Output vs. JPL Horizons
- **Unverified Aspect:** Sub-arcsecond planetary longitude comparisons against NASA JPL Horizons online ephemeris.
- **Reason:** The test suite does not include a test pulling live JPL Horizons ephemerides. The engine operates in Moshier semi-analytical mode due to the absence of local `.se1` files.
- **Risk:**
  1. Planetary longitudes are verified against Lahiri standards for known historical charts and DrikPanchang, but drift by a few arcseconds may occur for epochs before 1900 or after 2050.

---

### 3. Non-IST International Location Reference Oracles
- **Unverified Aspect:** Ground-truth validation of Panchang limbs, Sunrise/Sunset, and Ascendant for international non-IST cities (e.g., London, New York, Sydney, Tokyo).
- **Reason:** All reference tests in [`backend/tests/test_drikpanchang_reference.py`](file:///c:/Desktop/astro_may_res%20(2)/astro-platform/backend/tests/test_drikpanchang_reference.py) test Indian cities (Chennai and Leh) under IST (+05:30).
- **Risk:**
  1. Sunrise/Sunset formulas and Udaya Tithi determinations for extreme northern latitudes or daylight saving transitions (DST) remain unvalidated against external oracles.

---

### 4. Production Database Performance Under Concurrent Write Load
- **Unverified Aspect:** PostgreSQL connection pool saturation, transaction locking, and query execution plans under high concurrency.
- **Reason:** Tests were run against local SQLite and in-memory test databases; no live PostgreSQL cluster with high concurrent traffic was available in this session.
- **Risk:**
  1. Connection pool exhaustion during spikes in user feedback or activity logging.
  2. Alembic migration rollback procedures on live production PostgreSQL data have not been rehearsed.

---

### 5. Multi-Tenant and Role-Based Privilege Escalation
- **Unverified Aspect:** Complex tenant isolation and multi-role access control beyond single-admin checks.
- **Reason:** The database schema only distinguishes between regular users and `is_admin = True`. No organizational multi-tenancy exists in code.
- **Risk:**
  1. Admin routes (`/api/admin/*`) rely strictly on `request.session.get("admin") == "true"`. If session encryption keys (`SESSION_SECRET_KEY`) leak, privilege escalation is trivial.

---

### 6. Mobile Browser Rendering & SVG Visualizer Viewport Layout
- **Unverified Aspect:** Visual rendering and touch interactivity of North Indian Kundali SVGs on physical iOS Safari and Android Chrome screens.
- **Reason:** Automated tests validate HTML and JSON API responses; visual UI was not rendered in physical mobile viewports during read-only backend testing.
- **Risk:**
  1. Fixed SVG dimensions (`viewBox="0 0 600 400"`) in [`frontend/kundali.js`](file:///c:/Desktop/astro_may_res%20(2)/astro-platform/frontend/kundali.js) may require manual pinching or overflow on small mobile devices (< 360px width).

---

### 7. Redis Queue Recovery After Worker Crash
- **Unverified Aspect:** Behavior of in-flight jobs on `queue:astrologic_jobs` if a background worker (`narrative_worker.py`) crashes mid-execution (OOM kill or network timeout).
- **Reason:** The lightweight Redis queue implementation uses `RPOP` / `LPUSH` without a Redis Streams acknowledgment (`XACK`) or dead-letter queue (DLQ) mechanism.
- **Risk:**
  1. If a worker terminates while processing an LLM narrative, the job is popped from the queue and permanently lost, leaving the job state stuck in `RUNNING` in the Redis cache until the 24-hour TTL expires.
